# 0.5 Embedding 与向量空间

## 本章目标

建立对 Embedding 的直觉理解，能够设计基于语义相似度的系统方案。

**关键约束：无数学公式，关注语义匹配的设计应用。**

## 核心知识点

### 1. Embedding 的本质

**一句话定义：**
Embedding 是将文本（或图像、代码等）转换成数字向量的过程，使得语义相似的文本在向量空间中也相似。

**核心直觉：**
就像把词语放到一个多维坐标系中，意思相近的词离得近，意思不同的词离得远。

**类比：颜色空间**
- RGB 颜色空间：红色 (255,0,0)，绿色 (0,255,0)
- 红和绿在空间中距离很远
- 深红和浅红在空间中距离很近

**Embedding 空间：**
- 每个词/句子是一个高维向量（通常 768 维或 1536 维）
- "国王"和"女王"在向量空间中很接近
- "国王"和"苹果"在向量空间中很远

### 2. 为什么 Embedding 有效

**语义编码：**
Embedding 模型通过训练学会了：
- 上下文相似的词，向量也相似
- 语义关系（如"国王-男人+女人≈女王"）
- 主题、情感、语义的编码

**训练过程直觉：**
1. 模型阅读海量文本
2. 学习"哪些词经常一起出现"
3. 形成语义向量表示
4. 相似的上下文 → 相似的向量

### 3. 向量相似度计算

**核心指标：余弦相似度**

**直觉：**
两个向量的夹角越小，相似度越高。

- 夹角 0°：完全相同方向，相似度 = 1
- 夹角 90°：垂直，相似度 = 0
- 夹角 180°：相反方向，相似度 = -1

**应用场景：**
| 相似度 | 含义 | 应用 |
|--------|------|------|
| 0.9+ | 非常相似 | 去重、匹配 |
| 0.7-0.9 | 相似 | 推荐、搜索 |
| 0.5-0.7 | 相关 | 相关推荐 |
| <0.5 | 不相关 | 过滤 |

### 4. Embedding 的层级

#### 词级别（Word Embedding）
**粒度：** 单个词
**适用：** 词义分析、词类比
**局限：** 一词多义（"银行"可以是金融机构也可以是河岸）

#### 句子级别（Sentence Embedding）
**粒度：** 完整句子
**适用：** 语义搜索、句子匹配、分类
**特点：** 考虑上下文语境

#### 文档级别（Document Embedding）
**粒度：** 长文本
**适用：** 文档聚类、主题建模
**生成方式：** 平均池化、特殊标记、分段处理

### 5. Embedding 模型选型

**开源模型：**

| 模型 | 维度 | 特点 | 适用场景 |
|------|------|------|----------|
| text-embedding-ada-002 | 1536 | OpenAI，效果好 | 通用语义搜索 |
| text-embedding-3-small | 1536 | 更便宜、更快 | 成本敏感场景 |
| text-embedding-3-large | 3072 | 更高精度 | 高精度要求 |
| BGE | 768/1024 | 中文优化 | 中文场景 |
| GTE | 768 | 轻量高效 | 实时应用 |
| M3E | 768 | 中文开源 | 本地部署 |

**选型考量：**
1. **语言：** 中文场景选中文优化模型
2. **成本：** API 调用 vs 本地部署成本
3. **延迟：** 模型大小与推理速度
4. **精度：** 不同模型的准确率差异
5. **隐私：** 敏感数据需要本地部署

### 6. Embedding 在 RAG 中的作用

**RAG 流程中的 Embedding：**

```
用户问题 → Embedding → 向量检索 → 相关文档 → LLM 生成回答
                ↑
文档库 → Embedding → 向量数据库（存储）
```

**关键作用：**
1. **语义匹配：** 找到意思相关的内容，而非关键词匹配
2. **多语言：** 不同语言的相似内容可以匹配
3. **容错性：** 错别字、同义词都能匹配

**示例：**
- 用户问："怎么退货？"
- 能匹配到："退款流程说明"、"如何申请退款"、"Return Policy"
- 传统关键词搜索只能匹配"退货"字样

## 设计实战

### 语义相似度应用场景

| 场景 | 实现方式 | 相似度阈值 |
|------|----------|------------|
| 智能客服 | 用户问题匹配知识库 | 0.75 |
| 重复内容检测 | 新内容与已有内容比对 | 0.85 |
| 推荐系统 | 用户兴趣匹配内容 | 0.60 |
| 分类任务 | 文本与类别描述匹配 | 0.70 |
| 语义搜索 | 查询与文档匹配 | 0.65 |
| 聚类分析 | 相似内容自动分组 | 动态确定 |

### 向量数据库选型

**主流向量数据库：**

| 数据库 | 特点 | 适用场景 |
|--------|------|----------|
| Pinecone | 托管服务、易用 | 快速启动、中小规模 |
| Weaviate | 开源、多模态 | 需要灵活定制 |
| Milvus | 高性能、大规模 | 海量数据、高并发 |
| Chroma | 轻量、本地优先 | 开发测试、小项目 |
| pgvector | PostgreSQL 扩展 | 已有 PG 基础设施 |
| Redis | 内存存储、低延迟 | 实时应用、缓存 |

**选型决策矩阵：**

```
数据规模?
    │
    ├── <100K → Chroma / pgvector
    │
    ├── 100K-10M → Weaviate / Pinecone
    │
    └── >10M → Milvus / 自建

延迟要求?
    │
    ├── <50ms → Redis / 内存方案
    │
    └── 可接受 100-500ms → 常规向量数据库

运维能力?
    │
    ├── 强 → 开源方案（Milvus/Weaviate）
    │
    └── 弱 → 托管服务（Pinecone）
```

## 本章小结（建议学习时长：约 30 分钟）

**能力产出：**
- ✅ **一张概念图**：Embedding 工作原理示意图（展示文本到向量的转换过程，向量空间中的相似关系，标注语义编码与余弦相似度）

**核心要点回顾：**
- Embedding 将语义转化为向量，让计算机能"理解"语义相似性
- 余弦相似度是衡量语义相似的标准方法
- 不同粒度的 Embedding（词/句/文档）适用不同场景
- Embedding 是 RAG 的核心组件，实现语义检索
- 选型要考虑语言、成本、延迟、隐私等因素
