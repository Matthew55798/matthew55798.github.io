# 0.4 LLM 训练流程与能力边界

## 本章目标

理解 LLM 的训练过程和能力边界，能够识别 LLM 的适用场景与风险点。

**关键约束：无数学推导，关注能力判断与风险识别。**

## 核心知识点

### 1. LLM 训练的三阶段

#### 阶段一：预训练（Pre-training）

**目标：** 让模型学会语言的语法、语义、世界知识

**过程：**
- 在海量文本上训练（互联网文本、书籍、代码等）
- 模型学习预测下一个 Token
- 学会语法、常识、推理模式

**类比：** 像学生阅读大量书籍，学习语言和世界知识

**产出：** Base 模型（基础模型）
- 能续写文本
- 但不会对话、不遵循指令
- 可能生成有害内容

#### 阶段二：监督微调（SFT - Supervised Fine-Tuning）

**目标：** 让模型学会遵循指令、进行对话

**过程：**
- 准备高质量的指令-回答对（人工标注）
- 在预训练模型基础上微调
- 学习"用户问什么，我该怎么答"

**类比：** 学生学会了知识，现在学习如何回答问题

**产出：** Instruct 模型（指令模型）
- 能进行对话
- 能遵循指令
- 输出格式更规范

#### 阶段三：RLHF（人类反馈强化学习）

**目标：** 让模型输出更符合人类偏好、更安全

**过程：**
1. 训练奖励模型（学习人类偏好）
2. 用强化学习优化模型输出
3. 奖励好的回答，惩罚差的回答

**类比：** 考试打分机制 - 回答得好给高分，回答得差给低分

**产出：** Aligned 模型（对齐模型）
- 输出更安全、更有帮助
- 会拒绝有害请求
- 价值观更接近人类

### 2. 能力涌现（Emergent Abilities）

**什么是涌现能力？**

当模型参数达到某个阈值后，突然"学会"了一些新能力。

**典型涌现能力：**

| 能力 | 描述 | 出现阈值 |
|------|------|----------|
| 上下文学习 | 看几个示例就能学会新任务 | ~10B 参数 |
| 思维链 | 逐步推理解决问题 | ~100B 参数 |
| 代码生成 | 理解和生成代码 | ~100B 参数 |
| 多语言 | 跨语言理解和生成 | ~100B 参数 |
| 指令遵循 | 理解并执行复杂指令 | ~100B 参数 |

**工程启示：**
- 小模型（<10B）能力有限，适合特定任务
- 大模型（>100B）通用能力强，但成本高
- 根据任务选择合适规模的模型

### 3. LLM 的能力边界

#### 擅长什么？

✅ **文本理解与生成**
- 问答、摘要、翻译
- 文案撰写、代码生成

✅ **模式识别**
- 从示例中学习规律
- 分类、提取、格式化

✅ **推理（有限）**
- 简单逻辑推理
- 常识推理

✅ **创意与多样性**
- 头脑风暴
- 多种方案生成

#### 不擅长什么？

❌ **数学计算**
- 大数乘法、复杂公式
- 容易出错，需要验证

❌ **实时信息**
- 知识有截止日期
- 不知道今天的新闻

❌ **确定性执行**
- 同样的输入可能不同输出
- 不适合需要 100% 准确性的场景

❌ **物理世界交互**
- 不能真正"看到"图片
- 不能真正"听到"声音（多模态除外）

❌ **深度专业领域**
- 医学诊断、法律咨询
- 需要专业知识验证

### 4. 幻觉（Hallucination）

**什么是幻觉？**

LLM 生成看起来合理但实际上错误的内容。

**幻觉类型：**

| 类型 | 示例 | 识别方法 |
|------|------|----------|
| 事实幻觉 | 编造不存在的历史事件 | 事实核查 |
| 引用幻觉 | 编造论文、书籍引用 | 查证来源 |
| 逻辑幻觉 | 推理过程看似正确但结论错误 | 逻辑验证 |
| 指令幻觉 | 声称执行了操作但实际上没有 | 结果验证 |

**为什么会产生幻觉？**

1. **训练数据噪声：** 学到了错误信息
2. **概率生成机制：** 总是生成"最可能"的下个词，不一定是"最正确"的
3. **知识盲区：** 遇到不知道的内容，会"编造"而非承认不知道
4. **指令压力：** 被期望给出答案，即使不确定

### 5. 幻觉缓解策略

#### 设计层面的对策

| 策略 | 适用场景 | 实现难度 |
|------|----------|----------|
| RAG 增强 | 需要准确知识的场景 | 中等 |
| 限制回答范围 | 特定领域应用 | 低 |
| 多模型验证 | 高风险场景 | 高 |
| 置信度提示 | 所有场景 | 低 |
| 人工审核 | 关键决策 | 中 |

#### Prompt 层面的对策

**1. 明确要求不确定时承认**
```
如果无法确定答案，请明确说"我不知道"，不要编造。
```

**2. 要求提供依据**
```
回答时请说明你的依据是什么。
```

**3. 分步验证**
```
先列出你的推理过程，再给出结论。
```

## 设计实战

### LLM 能力评估矩阵

为你的场景评估 LLM 适用性：

| 评估维度 | 评估问题 | 风险等级 |
|----------|----------|----------|
| 准确性要求 | 是否允许错误？ | 高/中/低 |
| 实时性要求 | 是否需要最新信息？ | 高/中/低 |
| 可解释性要求 | 是否需要说明理由？ | 高/中/低 |
| 成本约束 | 单次调用成本上限？ | 数值 |
| 延迟约束 | 响应时间要求？ | 数值 |
| 安全要求 | 错误后果严重程度？ | 高/中/低 |

**决策规则：**
- 高准确性 + 高风险 → 需要人工审核或替代方案
- 高实时性 → 需要 RAG 或外部数据接入
- 高成本约束 → 考虑小模型或缓存策略

### 幻觉风险检查清单

**使用 LLM 前必查：**

- [ ] 这个场景是否对准确性有严格要求？
- [ ] 如果 LLM 给出错误答案，后果是什么？
- [ ] 是否有验证机制可以检查 LLM 输出？
- [ ] 用户是否知道这是 AI 生成的内容？
- [ ] 是否有机制让用户反馈错误？

**高风险场景识别：**
- 医疗诊断建议
- 法律意见
- 金融投资建议
- 安全关键决策
- 涉及个人隐私的输出

## 本章小结（建议学习时长：约 20 分钟）

**能力产出：**
- ✅ **一张概念图**：LLM 能力边界雷达图（8 个能力维度标注适用与不适用区域，区分不同规模模型的能力曲线）
- ✅ **一句话总结**：学完本章，你能够评估 LLM 在特定场景的适用性，识别幻觉风险并设计有效的缓解机制与降级方案

**核心要点回顾：**
- LLM 训练三阶段：预训练（学知识）→ SFT（学对话）→ RLHF（学偏好）
- 大模型有涌现能力，但也有幻觉风险
- LLM 擅长文本，不擅长精确计算和实时信息
- 设计时要评估风险，建立验证和降级机制

3. 如何设计一个"知道不知道"的系统，让 LLM 在不确定时诚实表达？
