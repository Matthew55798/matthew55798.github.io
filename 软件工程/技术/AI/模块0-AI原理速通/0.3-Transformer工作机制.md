# 0.3 Transformer 工作机制

## 本章目标

建立对 Transformer 架构的直觉理解，能够在设计层面做出 Token 成本和上下文管理决策。

**关键约束：无数学公式，关注工程直觉。**

## 核心知识点

### 1. 注意力机制直觉

**核心问题：** 在处理长文本时，模型如何知道哪些词更重要？

**直觉类比：阅读长篇文章**
当你阅读时：
- 你会关注标题和关键词
- 你会记住上下文关系
- 你会自动忽略不重要的词（"的"、"了"等）

**注意力机制就是让这个"关注什么、忽略什么"的过程可计算化。**

### 2. Tokenization：文本如何变成数字

**为什么需要 Tokenization？**

计算机只能处理数字，不能处理文字。

**Tokenization 的过程：**
```
原文："我爱北京天安门"
    ↓
分词：["我", "爱", "北京", "天安门"]
    ↓
映射：[1024, 2056, 3891, 4523]
    ↓
输入模型
```

**Token 的特点：**
- 不是简单的按字或按词分割
- 使用子词（subword）技术："天安门" = "天" + "安门"
- 常用词是完整 Token，罕见词是多个 Token 组合

**中英文 Token 数量差异：**
- 英文：1 个词 ≈ 1.3 个 Token
- 中文：1 个字 ≈ 1-2 个 Token（取决于分词器）

**工程启示：**
- 同样长度，中文成本可能更高
- 英文缩写更省 Token

### 3. 自注意力机制（Self-Attention）

**核心直觉："这个词和哪些词相关？"**

**类比：阅读理解中的指代消解**
句子："小明把书给了小红，她很高兴。"
- "她"指谁？需要看前文
- 注意力机制计算"她"与"小明"、"小红"的相关性
- 发现"她"和"小红"相关性更高

**注意力计算的三个角色：**
1. **Query（查询）：** 我要找什么？
2. **Key（键）：** 我有什么信息？
3. **Value（值）：** 实际内容是什么？

**工作流程：**
```
对于每个词：
    1. 生成 Query、Key、Value
    2. 计算 Query 与所有 Key 的相似度
    3. 相似度作为权重，加权求和得到输出
    4. 相似度高的词贡献更大
```

### 4. Transformer 架构概览

**核心组件：**

```
输入 → [Embedding + 位置编码] → [Encoder × N] → 输出
                          ↓
                   [多头注意力]
                   [前馈神经网络]
                   [残差连接 + 归一化]
```

**编码器（Encoder）：**
- 处理输入文本
- 理解上下文关系
- 输出上下文表示

**解码器（Decoder）：**
- 生成输出文本
- 逐步预测下一个 Token
- 只能看到已生成的内容（掩码注意力）

**GPT 类模型：** 只有解码器
**BERT 类模型：** 只有编码器
**T5 类模型：** 编码器 + 解码器

### 5. 计算复杂度与 Token 数量

**关键公式（直觉版）：**

计算量 ∝ Token 数量²

**含义：**
- Token 翻倍，计算量变成 4 倍
- Token 翻 3 倍，计算量变成 9 倍
- 长文本处理成本很高

**为什么？**
每个 Token 都要和每个其他 Token 计算注意力
- 10 个 Token：10 × 10 = 100 次计算
- 100 个 Token：100 × 100 = 10,000 次计算

**工程启示：**
- 上下文窗口不是越大越好
- 要合理控制输入长度
- 长文档需要分段或摘要

### 6. 上下文窗口管理

**什么是上下文窗口？**

模型能"记住"的 Token 数量上限。

**常见窗口大小：**
- GPT-3.5：4K（约 3000 字）
- GPT-4：8K / 32K / 128K
- Claude 3：200K
- Llama 2：4K / 8K

**上下文超限的后果：**
- 超出部分被截断
- 模型看不到被截断的内容
- 可能导致信息丢失

**长文本处理策略：**

1. **截断（Truncation）**
   - 保留开头 + 结尾，截断中间
   - 简单但可能丢失关键信息

2. **分段（Chunking）**
   - 将长文档分成小块
   - 分别处理或检索相关块

3. **摘要（Summarization）**
   - 先提取关键信息
   - 用摘要代替原文

4. **检索增强（RAG）**
   - 只检索相关片段
   - 详见 1.4 章节

## 设计实战

### Token 成本计算

**计算公式：**
```
总 Token = 输入 Token + 输出 Token
总成本 = 输入 Token × 输入单价 + 输出 Token × 输出单价
```

**示例：**
- 输入：1000 Token，单价 $0.001/1K
- 输出：500 Token，单价 $0.002/1K
- 成本 = (1000/1000) × 0.001 + (500/1000) × 0.002 = $0.002

**Token 优化策略：**

| 策略 | 做法 | 效果 |
|------|------|------|
| 精简 Prompt | 删除冗余说明 | 减少 10-30% |
| 使用缩写 | "API" 代替 "Application Programming Interface" | 大幅减少 |
| 结构化输入 | 使用 JSON 而非自然语言描述 | 更紧凑 |
| 缓存响应 | 相同输入直接返回缓存 | 降低重复成本 |
| 选择合适的模型 | 简单任务用小模型 | 成本差 10-100 倍 |

### 上下文窗口设计

**设计决策矩阵：**

| 场景 | 窗口策略 | 实现方式 |
|------|----------|----------|
| 单轮问答 | 直接使用 | 控制输入长度 < 窗口 |
| 多轮对话 | Sliding Window | 保留最近 N 轮 |
| 文档问答 | RAG | 检索相关片段 |
| 长文档摘要 | Map-Reduce | 分段摘要再综合 |
| 代码生成 | 代码分段 | 按文件/函数处理 |

```

示例句子："猫坐在垫子上，因为它很温暖"

```

**提示词：**
```

假设：
- 平均输入：500 Token
- 平均输出：300 Token
- 模型：GPT-4（输入 $0.03/1K，输出 $0.06/1K）

请输出：
1. 单次对话成本计算
2. 日/月/年成本估算
3. 不同优化策略下的成本对比表（基准 vs 精简 Prompt vs 缓存 50% vs 使用小模型）
```

## 本章小结（建议学习时长：约 20 分钟）

**能力产出：**
- ✅ **一张概念图**：Transformer 工作机制流程图（从输入到输出的完整流程，标注关键组件：Embedding、注意力、前馈网络）
- ✅ **一句话总结**：学完本章，你能够根据 Token 成本和上下文窗口限制，设计合理的输入输出策略和成本控制方案

**核心要点回顾：**
- Transformer 通过注意力机制让模型知道"关注什么、忽略什么"
- Token 是文本的数字表示，成本按 Token 计费
- 计算复杂度与 Token 数量平方成正比
- 设计时要考虑：Token 成本、上下文窗口限制、长文本处理策略
