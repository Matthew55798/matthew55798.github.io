## 1. 课程概述

### 1.1 课程定位

本课程**聚焦架构设计**，帮助 Java 工程师理解如何将 AI 能力接入现有系统。

**课程性质：** 设计能力课程，不是编程课程

**核心目标：**
1. 理解 LLM/RAG/Agent/Tool 核心概念与能力边界
2. 能在设计层面将 AI 能力接入现有系统
3. 能用 AI 工具辅助理解、设计、验证方案（Vibe Coding）
4. 最终能独立完成"AI 增强系统"的架构设计

### 1.2 目标人群

- **经验：** 2-8 年 Java 开发经验
- **技术栈：** 熟悉 Spring Boot 生态
- **AI 基础：** 对 AI 了解有限，希望系统性学习
- **学习目标：** 成为 AI 系统架构师，不是 AI 算法工程师

### 1.3 关键约束

| 约束 | 说明 |
|------|------|
| 理论科普优先 | 不陷入数学推导，用直觉理解原理 |
| 原理必须讲清楚 | Transformer、Embedding、RAG、ReAct 核心概念 |
| 认知能力产出 | 每章能画出图、写出设计说明、列出决策清单 |
| 无代码实现 | 可以有伪代码或配置示意，但不作为主体 |
| 设计导向 | 每章必须回答"学完能设计出什么？" |

### 1.4 课程主线

以**电商客服系统 AI 增强之旅**为主线案例：

```
基线系统 → AI 问答接入 → RAG 增强 → Agent 化升级 → Tool 集成 → 完整 AI 增强系统
```

## 5. AI 辅助设计工作流

### 5.1 流程概览

AI-Assisted Design Flow（AIAD）是与 AI 协作完成架构设计的结构化流程。

```
需求澄清 → 概念学习 → AI生成草案 → 人工评审 → 边界推演 → 最终文档
```

### 5.2 六阶段详解

| 阶段 | 名称 | AI 作用 | 人工职责 | 产出 |
|------|------|---------|----------|------|
| 1 | 需求澄清 | 生成问题清单、结构化框架 | 回答问题、确认约束 | 澄清后需求 |
| 2 | 概念学习 | 解释概念、提供类比 | 确认理解、追问 | 掌握后概念 |
| 3 | 生成草案 | 生成架构图、决策表 | 提供输入、指导方向 | 设计草案 |
| 4 | 人工评审 | 提供检查清单 | 审查修正、决策 | 修正后草案 |
| 5 | 风险推演 | 推演边界、生成测试用例 | 评估确认 | 优化后方案 |
| 6 | 最终文档 | 整理结构化文档 | 审核发布 | 设计文档 |

## 6. 课程设计原则

### 6.1 五大核心原则

**原则 1：理论服务于设计**
- 原理讲解为设计决策提供依据
- 不追求理论深度
- 无数学公式

**原则 2：能力导向产出**
- 每章都有明确的设计产出物
- 产出形式：架构图、决策树、检查清单、设计文档
- 学完每章能做出具体的设计决策

**原则 3：渐进式演进**
- 跟随主线案例逐步构建完整系统设计
- 从简单到复杂，每步都有明确产出
- 制品递进，形成完整方案

**原则 4：AI 辅助而非替代**
- 教授如何与 AI 协作完成设计
- AI 生成草案，人工审查决策
- 培养人机协作能力

**原则 5：工程化思维**
- 关注成本、延迟、安全、可维护性
- 生产环境考量
- 权衡决策训练

### 6.2 避坑指南

| 坑 | 如何避免 |
|----|----------|
| 理论过重 | 每章设计实战占比 ≥ 40% |
