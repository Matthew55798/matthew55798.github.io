# Agent 架构

Agent（智能体）是指能够自主感知环境、推理并采取行动以完成目标的 AI 系统。

本文从最简单的循环到多 Agent 协作，一文读懂六种主流架构的原理与适用场景。

---

## 什么是 Agent 架构

在 AI 应用开发中，Agent（智能体）是指能够感知环境、自主做出决策、并采取行动的 AI 系统。

Agent 的本质：感知 → 推理 → 行动

Agent 核心循环：
```
感知环境 → 推理决策 → 执行行动 → 观察结果，继续循环
```

---

## 架构一：单 Agent 循环（Single Agent Loop）

最基础也最直观的架构，一个 Agent 从头到尾独立完成所有任务。

### 工作原理

1.  **感知**：读取当前状态——文件内容、环境变量、之前步骤的输出结果
2.  **推理**：LLM 根据上下文决定下一步动作
3.  **行动**：执行工具调用，工具的执行结果会被追加到上下文中，进入下一轮循环

#### 优点
-   实现最简单，易于调试
-   适合任务边界清晰的场景

#### 缺点
-   上下文窗口容易撑满
-   复杂任务中容易"偏航"
-   无法并行处理多个子任务

**最佳适用场景**：修复一个 bug、编写一个函数、回答一个具体问题。

---

## 架构二：规划 + 执行（Plan & Execute）

将"想清楚要做什么"和"实际去做"分离为两个独立阶段，提升任务的可预测性和可审计性。

### 两种变体

| 变体 | 行为 | 典型场景 |
|------|------|---------|
| 静态规划 | 计划一次性生成，按顺序线性执行 | 流程固定、步骤明确的任务 |
| 动态规划 | 每执行一步后重新评估，根据结果调整后续计划 | 结果不确定的任务 |

> Claude Code 的 Plan Mode 就是这个架构的体现——点击"计划"后，AI 先输出一份详细计划供你审查，确认后才开始执行。

#### 优点
-   执行前可人工审查计划
-   推理和执行职责分离，清晰
-   对长任务友好

#### 缺点
-   初始计划可能不够准确
-   两阶段增加了延迟

---

## 架构三：多 Agent 协作（Multi-Agent）

一个 Orchestrator（协调者）负责任务拆解和调度，多个 Subagent 各司其职，并行或串行地完成子任务。

### 核心优势

每个子 Agent 拥有独立的上下文窗口。代码审查 Agent 深度阅读代码不会影响性能分析 Agent 的判断。

#### 优点
-   天然支持并行，速度快
-   子 Agent 各自独立，上下文互不干扰
-   可以专门化每个子 Agent 的角色

#### 缺点
-   协调逻辑复杂，调试困难
-   多个 Agent 并行的 Token 成本更高

---

## 架构四：反思与自我修正（Reflection）

在 Agent 的输出环节加入质量评估，不满意则重新生成或修正，形成内部迭代循环。

### 两种实现方式

| 方式 | 机制 | 优点 | 缺点 |
|------|------|------|------|
| 自我反思 | 同一个模型先执行再评估自己的输出 | 实现简单，无额外模型成本 | 模型可能对自己的错误"视而不见" |
| Critic 模型 | 用独立的评判模型评估执行模型的输出 | 更客观，能发现执行模型盲区 | 增加模型调用成本和延迟 |

---

## 架构五：RAG + Agent（检索增强型智能体）

在 Agent 的工具集里加入向量检索能力，让 Agent 在推理过程中动态查询外部知识库。

### 与普通 RAG 的关键区别

-   **普通 RAG**：被动、一次性，用户提问时固定检索一次
-   **RAG + Agent**：自主判断在推理的哪个环节需要补充知识、需要检索什么，并可以多次查询

---

## 架构六：工作流编排（Workflow / DAG）

把 Agent 行为固化为一张有向无环图（DAG），每个节点是一个 LLM 调用或工具调用，边表示数据依赖关系。

### 纯 Agent vs DAG 工作流

| 特性 | 纯 Agent | DAG 工作流 |
|------|---------|-----------|
| 流程控制 | 模型自主决定下一步 | 预定义的 DAG 图决定 |
| 可预测性 | 低，每次运行路径可能不同 | 高，运行路径确定 |
| 可调试性 | 难，依赖日志追踪 | 易，每个节点输入输出明确 |
| 灵活性 | 高，可应对意外情况 | 低，只能走预定义路径 |

---

## 横向对比与如何选择

| 架构 | 自主性 | 可预测性 | 并行能力 | 适合任务复杂度 | 典型实现 |
|------|--------|---------|---------|--------------|---------|
| 单 Agent 循环 | 高 | 低 | 无 | 中低 | Claude Code 默认模式 |
| 规划 + 执行 | 中 | 中 | 部分 | 中高 | Claude Code Plan Mode |
| 多 Agent 协作 | 高 | 低 | 强 | 高 | AutoGen, CrewAI |
| 反思/自我修正 | 中 | 中 | 无 | 中 | Reflexion, Self-Refine |
| RAG + Agent | 高 | 中 | 无 | 中高 | LangChain RAG Agent |
| 工作流编排 | 低 | 高 | 强 | 高（固定流程） | LangGraph, Prefect |

### 常见组合模式

-   **工作流编排 + 多 Agent**：用 DAG 定义主流程，每个节点内部是一个独立的 Agent
-   **多 Agent + RAG**：多个 Subagent 共享同一个向量知识库
-   **规划执行 + 反思**：先规划再执行，但每个步骤执行后加入反思环节

---

## 总结

六种 Agent 架构覆盖了从高度自主到高度可控的完整光谱。

选择架构时，核心考量只有两个：你需要多大的灵活性来应对意外情况，以及你需要多大的确定性来保证结果可靠。

**从简单开始，在确实需要时才增加复杂度，这是 Agent 架构选型的第一原则。**
