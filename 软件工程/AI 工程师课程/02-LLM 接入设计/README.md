## 章节目录

### 1.1 接入模式全景

**设计主题**：同步、异步、流式、批量 — 4 种调用模式的选择

**主要概念**：
- **同步调用**：阻塞等待完整响应（类似 `CompletableFuture.get()`）
  - 适用：简单问答、表单校验、内容翻译
  - 代价：连接占用时间 = LLM 推理时间（通常 1-10s）
- **异步调用**：提交请求后回调/轮询（类似消息队列）
  - 适用：耗时分析、批量处理、后台任务
  - 代价：增加系统复杂度
- **流式输出**：逐 Token 返回，首字节延迟极低（类似 SSE）
  - 适用：实时对话、代码补全、长文生成
  - 代价：客户端需要处理流式数据
- **批量调用**：多个请求打包处理
  - 适用：离线数据处理、定期报告生成
  - 代价：等待聚合延迟

**主线项目对接**（V2 → 设计 V2 的 LLM 接入层）：
- 设计 LLMClient 接口
- 决定什么场景用同步、什么用流式
- 设计成本估算表

**设计产出**：接入模式决策矩阵（5 个场景 × 4 种模式，标注适用性评分）

### 1.2 可靠性设计

**设计主题**：LLM 不可靠，系统要可靠

**主要概念**：
- **重试策略**：网络错误可重试，但 Token 错误不可重试
  - 哪些错误重试：超时、限流（429）、服务不可用（503）
  - 哪些不重试：Token 耗尽（400）、验证失败（401）、内容过滤（400）
- **指数退避**：1s → 2s → 4s → 8s → 最多 32s
- **熔断降级**：LLM 持续失败时触发熔断，降级策略是什么？
  - 降级方案：缓存结果 → 规则回答 → 人工接入
- **超时设置**：首字节超时 vs 全响应超时
- **幂等性**：重试安全，相同请求不产生副作用

**设计产出**：可靠性设计 Checklist（接入 LLM 的 10 项必备检查）

### 1.3 Prompt 工程：工程化视角

**设计主题**：Prompt 不是"写一句话"，是"工程资产"

**主要概念**：
- **模板管理**：
  - 结构化 Prompt：系统角色 + 上下文 + 任务 + 约束 + 输出格式
  - 变量注入：占位符策略、类型检查、空值处理
- **版本控制**：Prompt 变更需要记录和回滚
  - 变更记录：谁改的、为什么改、影响面
  - A/B 测试：版本对比、效果度量
- **测试策略**：
  - 单元测试：给定输入 → 预期输出模式
  - 回归测试：Prompt 变更后不破坏已有功能
- **Prompt as Code**：Prompt 版本管理 = 代码版本管理

**类比说明**：
- Prompt 管理 ≈ Java 配置文件管理（application.yml 的版本化）
- Prompt 测试 ≈ 单元测试（Given/When/Then）

**主线项目对接**（V2 → 设计 Prompt 模板管理规范）：
- 设计 Prompt 模板结构
- 制定版本控制策略
- 编写测试用例

**设计产出**：Prompt 管理规范（模板结构 + 版本策略 + 测试方案）

### 1.4 Prompt 安全

**设计主题**：别让 AI 被"骗"或"越权"

**主要概念**：
- **注入攻击**（Prompt Injection）：
  - 直接注入：用户输入恶意指令覆盖系统 Prompt
  - 间接注入：存储的内容中包含注入指令（RAG 场景）
- **越权风险**：AI 能访问它不该访问的数据
- **内容过滤**：生成不当内容的风险
- **安全边界设计**：
  - 输入层：校验 + 过滤 + 分类
  - 处理层：权限校验 + 最小权限原则
  - 输出层：内容审核 + 敏感信息过滤

**防御策略**：
1. Prompt 分片隔离（系统指令 vs 用户输入分开处理）
2. 输入白名单 + 黑名单
3. 输出前安全审核
4. 上下文隔离（用户 A 不能通过注入看到用户 B 的数据）

**设计产出**：Prompt 安全防御清单（5 类攻击 × 对应防护措施 + 检查项）
