## 章节目录

### 2.1 对话状态管理

**设计主题**：从"无状态调用"到"有状态系统"

**主要概念**：
- **会话 (Session)**：一次用户交互的完整生命周期
  - 创建：用户首次提问
  - 持续：用户在时间窗口内持续交互
  - 结束：超时关闭或用户主动关闭
- **记忆 (Memory)**：
  - **工作记忆**：当前对话的上下文窗口（Redis，TTL 30min）
  - **短期记忆**：用户近期历史（Redis，TTL 7 天）
  - **长期记忆**：用户画像、偏好、关键信息（MySQL/Redis Hash）
- **状态持久化**：
  - 何时存储：每轮对话后？定时？手动？
  - 存储格式：JSON 消息列表、压缩策略

**类比说明**：
- 记忆层级 ≈ JVM 内存分层（Eden → Survivor → Old Gen）
- 会话超时 ≈ HTTP Session 的 expiration

**主线项目对接**（V3 → 设计对话管理器）：
- 设计 Memory 层级结构
- 设计会话存储格式
- 设计消息持久化策略

**设计产出**：Memory 层级架构设计图 + 会话状态存储规范

### 2.2 上下文窗口策略

**设计主题**：Token 是有限资源，如何分配？

**主要概念**：
- **Token 预算分配**：
  ```
  ┌─────────────────────────────────┐
  │  上下文窗口总量 (如 8192 tokens)  │
  ├──────────┬──────────────────────┤
  │ 系统 Prompt    │ 500  (固定)       │
  │ 用户画像       │ 200  (可选加载)   │
  │ 对话历史       │ 3000 (滑动窗口)   │
  │ AI 回复的预算  │ 4000 (留足空间)   │
  │ 其他（RAG 等） │ 492  (按需加载)   │
  └──────────┴──────────────────────┘
  ```
- **消息裁剪策略**：
  - 滑动窗口：保留最近 N 轮，丢弃更早的
  - 摘要压缩：将多轮对话压缩为一段摘要
  - 智能选择：根据重要性选择保留哪些消息

- **Token 计数与限制**：
  - 请求前估算（预估输入 Tokens）
  - 响应时截断（输出超限时的处理）
  - 超 Token 预警（接近限值时触发降级）
- **缓存策略**：
  - 系统 Prompt 缓存（不变的可以复用）
  - 对话摘要缓存（压缩后的摘要缓存）

**设计产出**：Token 预算分配表 + 消息裁剪策略决策表

### 2.3 多用户对话设计

**设计主题**：隔离每个用户的对话空间

**主要概念**：
- **会话隔离**：
  - 会话存储隔离（按用户 ID 分 Key）
  - Token 预算隔离（每个用户独立计算）
- **数据隔离**：
  - 用户只能看到自己的历史
  - 跨租户数据注入风险（不能通过 AI 看到其他用户数据）
- **并发控制**：
  - 同一用户的多个活跃会话
  - 并发请求的一致性（哪个先执行？是否串行化？）
- **状态压缩**：
  - 大规模用户下的存储优化
  - 会话合并策略（相同用户的多个会话何时合并？）
- **多模态对话**（进阶，可选）：
  - 文本 + 图片 + 代码的对话混合

**类比说明**：
- 会话隔离 ≈ 线程隔离
- 多用户并发 ≈ 多线程并发（需要"锁"或"队列"控制）

**主线项目对接**（V3 → 设计多租户方案）：
- 设计会话 Key 命名规范
- 设计数据隔离方案
- 制定并发处理策略

**设计产出**：多租户对话架构草图 + 并发处理策略文档
