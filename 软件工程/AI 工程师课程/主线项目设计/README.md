# 课程主线：AI 增强后台系统设计演进

> **主线项目**：设计一套"AI 增强的企业内容管理系统"
>
> **业务背景**：某企业需要维护内部知识库、FAQ、操作指南。现有系统仅支持关键词搜索和人工维护。
>
> **演进目标**：从传统 CMS 逐步升级为具有 AI 问答、智能检索、自主 Agent 能力的下一代系统。

---

## 演进全景图

```
V1 普通后台系统
 │
 ├─ 用户查询 ──→ [业务系统] ──→ 数据库
 │                (关键词搜索)

 │                ↕ [对话管理器] ←→ [会话状态存储]
 │                ↕ [LLM 接入层]
 │                (多轮对话、追问)
 │
 ▼
V4 智能知识库（RAG）
 │
 ├─ 用户查询 ──→ [业务系统] ──→ 对话管理 ──→ LLM
 │                ↕ 检索增强
 │                ┌─→ [文档索引] ──→ 向量数据库
 │                │        ↓
 │                └─→ [知识库 API]
 │                        ↓
 │                  [文档处理 Pipeline]
 │                        ↓

 │                            ↕    ↕    ↕

 │
 ▼

 │
 ├─ 用户请求 ──→ [业务系统] ──→ [AI 编排层]

 ```

## V1：普通后台系统（基线）

**对应课程**：前置知识（无需学习）

### 系统定位
传统的企业内容管理系统：文章 CRUD + 关键词搜索 + 分类管理。

### 架构草图
```
┌──────────┐    ┌──────────────┐    ┌──────────┐
│   用户   │───→│  Spring Boot │────→│  MySQL   │
│  (GUI)   │    │  API 服务    │    │  数据库  │
└──────────┘    └──────────────┘    └──────────┘
                         ↓
                   Elasticsearch (可选)
                   (全文搜索)
```

### 设计制品
- **组件清单**：API Service、DB、Search Engine
- **数据模型**：Article、Category、Tag
- **核心流程**：发布流程、搜索流程

### 痛点（AI 要解决的问题）
1. 用户搜索只能靠关键词，语义理解差
2. 文档更新后同步慢，信息滞后
3. 复杂问题需要人工检索多篇文档后汇总
4. 操作繁琐，用户需要记住功能位置

## V2：AI 辅助问答（接入了 LLM）

**对应课程**：模块 1 — LLM 接入设计

### 新增组件
- **LLM 接入层**：统一封装 LLM 调用
- **Prompt 模板管理**：系统化管理 Prompt

### 架构变化
```
┌──────────┐    ┌──────────────┐    ┌──────────┐
│   用户   │───→│  Spring Boot │────→│  MySQL   │
│  (GUI)   │    │  API 服务    │    │  数据库  │
└──────────┘    └──────┬───────┘    └──────────┘
                       │
              ┌────────▼────────┐
              │   LLM 接入层     │
              │  ┌──────────┐  │
              │  │ 同步/异步 │  │
              │  │ 重试/降级 │  │
              │  └──────────┘  │
              └───┬───────────┘
                  │
              ┌───▼───────────┐
              │  Prompt 模板   │
              │   管理器       │
              └───────────────┘
                  │
              ┌───▼───────────┐
              │  LLM Provider │
              │  (OpenAI/     │
              │   通义/ etc)  │
              └───────────────┘
```

### V2 设计制品清单
1. **接入模式决策矩阵**：什么场景用同步、什么用异步
2. **LLM 接入层接口定义**（伪代码）：
   ```
   interface LLMClient {
       ChatResponse complete(PromptTemplate template, Map<String, Object> vars);
       StreamingResponse streamComplete(...);
       AsyncResult<ChatResponse> asyncComplete(...);
   }
   ```
3. **可靠性设计 Checklist**（V2 → V3 继承并扩展）
4. **Prompt 模板管理规范**（V2 首次建立，后续不断扩充）
5. **成本估算表**：QPS × Token 量 = 月成本预估

### 新权衡点
- **同步 vs 异步**：等待时间 vs 用户体验
- **流式 vs 非流式**：首字节延迟 vs 实现复杂度
- **模型选择**：质量 vs 成本 vs 延迟

## V3：多轮对话系统（有状态了）

**对应课程**：模块 2 — 对话与记忆系统

### 新增组件
- **会话管理器**：管理多轮对话状态
- **Memory 存储**：短期历史 + 长期记忆
- **上下文窗口管理器**：Token 预算分配

### 架构变化
```
┌──────────┐    ┌──────────────┐    ┌──────────┐
│   用户   │───→│  Spring Boot │────→│  MySQL   │
│  (GUI)   │    │  API 服务    │    │  数据库  │
└──────────┘    └──────┬───────┘    └──────────┘
                       │
              ┌────────▼────────┐
              │   LLM 接入层     │
              └────────┬────────┘
                       │
              ┌────────▼─────────┐
              │  对话管理器       │
              │  ┌─────────────┐ │
              │  │ Memory 系统  │ │
              │  │ 短期: Redis │ │
              │  │ 长期: MySQL │ │
              │  └─────────────┘ │
              └────────┬─────────┘
                       │
              ┌────────▼─────────┐
              │ 上下文窗口管理器  │
              │ - Token 预算     │
              │ - 消息裁剪策略   │
              └───────────────────┘
```

### V3 设计制品清单
1. **Memory 层级设计图**：
   - 工作记忆（当前会话窗口，Redis）
   - 短期记忆（用户近期对话，Redis TTL）
   - 长期记忆（用户画像/偏好，MySQL）
2. **Token 预算分配方案**：
   ```
   总窗口: 8K tokens
   ├── 系统 Prompt  : 500   (固定)
   ├── 检索知识     : 2000  (V4 阶段加入)
   ├── 对话历史     : 3000  (滑动窗口)
   └── 保留给输出   : 2500
   ```
3. **多租户隔离设计方案**：会话隔离、数据隔离、权限隔离
4. **会话状态序列化规范**：JSON 格式 + 压缩策略

### 新权衡点
- **记忆粒度**：存多少历史 → 影响上下文质量与成本
- **清理策略**：滑动窗口 vs 摘要压缩 → 细节 vs Token 节省
- **持久化频率**：每轮存 vs 定时存 → 一致性 vs 性能

## V4：智能知识库系统（RAG 全链路）

**对应课程**：模块 3 — RAG 知识库系统（重点模块）

### 新增组件
- **文档处理 Pipeline**：解析 → 切分 → Embedding
- **向量数据库**：存储和检索向量
- **检索服务**：混合检索 + 重排序
- **增强层**：检索结果注入 Prompt

### 架构变化
```
┌──────────┐    ┌──────────────┐    ┌──────────┐
│   用户   │───→│  Spring Boot │────→│  MySQL   │
│  (GUI)   │    │  API 服务    │    │  数据库  │
└──────────┘    └──────┬───────┘    └──────────┘
                       │
              ┌────────▼────────┐
              │   检索增强层     │
              │  ┌───────────┐  │
              │  │ 检索结果   │  │
              │  │ → 注入     │──┼──→ [LLM]
              │  │   Prompt  │  │
              │  └───────────┘  │
              └────────┬────────┘
                       │
              ┌────────▼────────┐
              │   检索服务       │
              │  ┌───────────┐  │
              │  │ 向量检索   │──┼──→ [向量数据库]
              │  │ 关键词检索 │──┼──→ [Elasticsearch]
              │  │ 重排序     │  │
              │  └───────────┘  │
              └────────┬────────┘
                       │
              ┌────────▼────────┐     ┌───────────┐
              │ 文档处理 Pipeline│←──→│ 数据源     │
              │  解析 → 切分     │     │ (文件/S3/ │
              │  Embedding → 入库│     │  API/DB) │
              └─────────────────┘     └───────────┘
```

### V4 设计制品清单
1. **文档处理 Pipeline 架构图**：
   ```
   PDF/Word/HTML
         ↓
   ┌─────┴─────┐        ┌─────────┐        ┌─────────┐
   │ 文档解析器 │───────→│ Chunk   │───────→│ Embed   │
   │ (按语义切) │        │ 策略器  │        │ 向量化  │
   └───────────┘        └─────────┘        └────┬────┘
                                                 ↓
   ┌───────────┐        ┌───────────┐    ┌─────┴─────┐
   │ 元数据标签 │←───────│ Metadata  │←───│ 向量存储  │
   │ (作者/日期/│        │ 标注器    │    │ (Milvus/) │
   │  分类/权限)│        └───────────┘    │ PGVector) │
   └───────────┘                         └───────────┘
   ```

2. **Chunk 策略决策表**：
   | Chunk 大小 | 适用场景 | 优缺点 |
   |-----------|---------|--------|
   | 固定字符数 | 通用文档 | 简单但可能切断语义 |
   | 按段落分割 | 结构文档 | 语义完整但可能超长 |
   | 语义分割    | 关键文档 | 精准但成本高 |

3. **检索策略对比矩阵**（5 种策略 × 3 个评估维度）
4. **知识库系统架构图**（完整版，含增量更新、版本管理）

### 新权衡点
- **Chunk 粒度**：细粒度（精准但碎片）vs 粗粒度（完整而冗余）
- **检索方式**：纯向量 vs 混合 vs BM25 → 语义理解 vs 关键词匹配
- **重排序**：值得多等 100ms 吗？精度提升幅度？
- **更新频率**：实时索引 vs 批量索引 → 一致性 vs 成本

## V5：自主 Agent 系统（AI 能动起来了）

**对应课程**：模块 4 — Agent 与 Tool 系统

### 新增组件
- **Agent 编排层**：ReAct 循环控制
- **Tool 注册中心**：API → Tool 转换
- **权限网关**：Tool 调用安全控制
- **审计日志**：Agent 决策追溯

### 架构变化
```
┌──────────┐    ┌──────────────┐    ┌──────────┐
│   用户   │───→│  Spring Boot │────→│  MySQL   │
│  (GUI)   │    │  API 服务    │    │  数据库  │
└──────────┘    └──────┬───────┘    └──────────┘
                       │
              ┌────────▼────────┐
              │   Agent 编排层   │
              │ ┌─────────────┐ │
              │ │ ReAct 循环   │ │
              │ │ 思考→选择   │ │
              │ │ 行动→观察   │ │
              │ └─────────────┘ │
              └────────┬────────┘
                       │
              ┌────────▼────────┐
              │  Tool 注册中心   │
              │ ┌─────┬───────┐ │
              │ │查询 │ 创建  │ │
              │ │Tool │ Tool  │ …
              │ │权限 │ 权限  │ │
              │ │校验 │ 校验  │ │
              │ └─────┴───────┘ │
              └────────┬────────┘
                       │
              ┌────────▼────────┐
              │   权限网关       │
              │ ┌─────────────┐ │
              │ │ 最小权限    │ │
              │ │ 沙箱执行    │ │
              │ │ 敏感拦截    │ │
              │ │ 审计日志    │ │
              │ └─────────────┘ │
              └─────────────────┘
```

### V5 设计制品清单
1. **Agent vs Workflow 决策树**：
   ```
   任务是否明确可枚举？
   ├── 是 → 用 Workflow（固定流程）
   └── 否 → 任务是否需要多步骤推理？
            ├── 是 → 用 Agent
            └── 否 → 用简单 LLM 调用
   ```

2. **Tool 接口规范**（JSON-Schema 风格）：
   ```json
   {
     "toolDef": {
       "name": "search_documents",
       "description": "根据语义搜索知识库文档",
       "parameters": {
         "query": { "type": "string", "description": "搜索关键词" },
         "limit": { "type": "integer", "max": 10 }
       },
       "returns": { "type": "array", "items": "Document" },
       "permissions": ["read:documents"]
     }
   }
   ```

3. **Tool 安全架构设计图**（三层防线）
4. **多 Agent 架构方案对比**：中心化路由 vs 去中心化协作

### 新权衡点
- **Agent vs 固定流程**：灵活性 vs 可控性
- **Tool 粒度**：粗粒度（少而通用）vs 细粒度（多而精准）
- **权限模型**：预审批 vs 运行时检查 → 安全性 vs 灵活性
- **循环控制**：最大步数 vs 自适应终止 → 安全性 vs 完成度

```
                       │
              ┌────────▼────────┐
              │   治理中间件     │
              │ ┌─────────────┐ │
              │ │ 成本控制    │ │ ← 日账单、预算告警
              │ │ 延迟优化    │ │ ← 缓存、预计算、流式
              │ │ 安全合规    │ │ ← 过滤、合规、审计

              │ └─────────────┘ │
              └─────────────────┘
```

### V6 设计制品清单
1. **成本优化策略图**（场景 × 模型 × 策略三维表）
2. **延迟优化决策树**（端到端延迟要求 → 方案选择）
3. **AI 系统安全合规清单**（数据/内容/权限/审计 四维表格）

### 新权衡点
- **模型分层**：多少比例请求该走哪个模型？

- **质量阈值**：什么分数算"合格"？不合格时降级策略？
- **用户反馈**：显式（评分按钮）vs 隐式（停留时长/复访率）
