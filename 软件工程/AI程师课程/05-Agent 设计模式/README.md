## 章节目录

### 4.1 Agent 基础

**设计主题**：什么时候该用 Agent？

**主要概念**：
- **什么是 Agent**：
  - 一个能自主"感知 → 思考 → 行动 → 观察"的 AI 系统
  - 核心循环：ReAct（Reason + Act）
  ```
  [思考] → 需要做什么？
    ↓
  [选择 Tool] → 选哪个工具？
    ↓
  [执行 Tool] → 调用工具
    ↓
  [观察结果] → 发生了什么？
    ↓
  [循环或终止] → 继续还是结束？
  ```
- **Agent vs Workflow**：
  | 特征 | Agent | Workflow |
  |------|-------|----------|
  | 决策主体 | AI 自主决定 | 流程定义 |
  | 灵活性 | 高，可处理未知场景 | 低，只处理预设场景 |
  | 可控性 | 低，行为不可预测 | 高，行为确定 |
  | 调试难度 | 困难 | 容易 |
  | 安全风 | 高，可能做出危险操作 | 低，边界清晰 |
- **何时用 Agent**：
  - 任务明确可枚举 → Workflow
  - 任务需要多步骤推理，且路径不固定 → Agent
  - 安全问题不严重 → Agent
  - 安全问题严重 → Workflow 或受控 Agent

**类比说明**：
- Agent ≈ 自主员工（给他任务，他自己想怎么做）
  - 优点：处理未知情况
  - 缺点：可能做出危险决策
- Workflow ≈ 操作流程书（照着做就行）
  - 优点：可控、可审计
  - 缺点：无法处理未预见的情况

**设计产出**：Agent vs Workflow 决策树（5 个评估维度）

### 4.2 Tool 设计模式

**设计主题**：如何把 Java API 变成 AI 可调用的 Tool

**主要概念**：
- **Tool 是什么**：
  - AI 的"手"—— AI 不能直接执行代码，需要通过 Tool 调用
  - Tool = 描述 + 参数定义 + 执行逻辑
  ```
  Tool 定义 {
      "name": "search_documents",
      "description": "搜索知识库中的文档，返回相关内容",
      "parameters": {
        "query": {
          "type": "string",
          "description": "搜索关键词"
        },
        "limit": {
          "type": "integer",
          "description": "返回数量限制",
          "max": 10,
          "default": 5
        }
      },
      "returns": {
        "type": "array",
        "items": {
          "doc_id": "string",
          "title": "string",
          "content": "string",
          "relevance_score": "float"
        }
      },
      "permissions": ["read:documents"]
  }
  ```
- **Tool 抽象层次**：
  - API → Tool：REST API / gRPC → AI 可调用的接口
  - 抽象原则：描述要精准（给 AI 看），参数要清晰（避免 AI 猜错）
  - Tool 粒度：粗粒度（少而泛）vs 细粒度（多而精确）
- **Tool 注册与发现**：
  - 注册中心：所有可用 Tool 的注册表
  - Tool 选择：AI 根据任务描述选择合适的 Tool
  - Tool 组合：一次调用多个 Tool 的编排方式

**主线项目对接**（V5 → 设计 Tool 接口规范）：
- 设计 Tool 接口规范（JSON Schema 风格）
- 设计 Tool 注册中心结构

**设计产出**：Tool 接口规范草案 + Tool 注册中心设计

### 4.3 Tool 安全与权限

**设计主题**：别让 AI 把系统搞坏了

**主要概念**：
- **最小权限原则**：
  - Tool 调用权限校验
  - 用户权限 → AI 权限映射
  - 敏感操作的额外审批层
- **沙箱执行**：
  - Tool 执行的环境隔离
  - 只读操作 vs 写操作分类处理
  - 敏感操作（删除、修改数据）需要显式确认
- **审计日志**：
  - 记录 AI 的每个 Tool 调用
  - 记录决策链（为什么选这个 Tool，输入是什么）
  - 异常行为检测
- **三级防线架构**：
  ```
  ┌─────────────┐       ┌─────────────┐       ┌─────────────┐
  │ 权限校验层   │       │ 执行控制层   │       │ 审计追踪层   │
  │ - 谁在调用   │       │ - 能不能执行 │       │ - 记录行为   │
  │ - 有什么权限 │       │ - 只读/读写  │       │ - 决策链     │
  │ - 是否越权   │       │ - 敏感拦截   │       │ - 异常检测   │
  └─────────────┘       └─────────────┘       └─────────────┘
  ```

**设计产出**：Tool 安全架构设计图（三层防线）

### 4.4 多 Agent 协作

**设计主题**：单个 Agent 不够用，多个 Agent 怎么协作？

**主要概念**：
- **协作模式对比**：
  | 模式 | 描述 | 优点 | 缺点 |
  |------|------|------|------|
  | 中心化路由 | 一个 Manager 负责任务分配 | 可控、易调试 | 单点瓶颈 |
  | 去中心化 | Agent 间直接协商 | 灵活、无单点 | 难调试 |
  | 分层架构 | Manager → Worker → Sub-worker | 层次清晰 | 复杂 |
- **消息传递**：
  - Agent 间如何通信？（共享状态 vs 消息队列）
  - 冲突解决：多个 Agent 给出矛盾结果？
- **多 Agent 的应用场景**：
  - 研究 Agent + 写作 Agent（一个查资料，一个写报告）
  - 路由 Agent + 领域 Agent（一个分任务，一个执行）

**设计产出**：多 Agent 架构对比图（3 种模式对比）

## 学习建议

- 本章的核心挑战：**可控性 vs 灵活性**的权衡
- Agent 看起来酷炫，但很多场景用 Workflow 更合适
- Vibe Coding：让 AI 帮你生成 Tool 接口草稿，但你需要评审安全
